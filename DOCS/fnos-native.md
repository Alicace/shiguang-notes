# 拾光便签完整原生适配

日期：2026-10-18。上游 1.12.0；原生应用独立版本 0.9.3。

## 范围

用户明确要求完整封装上游功能并加入飞牛账号、私有与授权共享空间、客户端 PNG、多屏界面和诊断导出。`fnos/m0` 是早期能力原型，不能当作完整应用交付；当前入口使用根目录 React/Express 应用。独立 Windows/macOS/Android 安装包仍是用户之前的后续计划。

## 运行与打包

- `FNOS_NATIVE=1`：服务器从飞牛统一网关取得 UID；只监听 Unix Socket，专用包用户运行；NAS 身份替换旧密码账号服务，管理账号在飞牛完成。
- 首开登录页：网关身份仍在每个请求上校验；应用内的登录页只用来让用户确认登录方式。NAS 账号可在设置里第一次设置应用密码（`/api/auth/password` 在原生模式且从未设置过时不需要旧密码），之后 `POST /api/auth/login` 可用「用户名 + 应用密码」登录同一份私有便签。带会话 Cookie 的请求只有在账号 `id` 与网关身份一致时才被接受，否则返回 401；`/api/auth/login` 与 `/api/auth/logout` 免 CSRF，但仍要求同源。
- 保留 `fnnotes-m0` 包标识和 `/app/fnnotes-m0/` 前缀以便升级；展示名称为拾光便签。
- `VITE_FNOS_NATIVE=1`：构建完整前端，适配路径、客户端 PNG、共享空间与原生设置。普通构建保留上游模式以运行其回归测试。
- `fnos/native/main.mjs`：校验目录与非 root 用户，载入本机受保护的服务配置与签名密钥，再启动完整应用。
- `fnos/native/build.mjs`：编译、复制完整界面和服务、字体/许可证/Skill，携带 Linux x64/glibc 的 Node 生产依赖，生成 FPK。无 Docker、Chromium 或生产 Playwright 依赖。
- `fnos/native/dev.mjs`：开发机模拟网关，1001/1002/1003 对应三个固定测试入口；不进入包。

构建命令：`npm run fnos:build`；打包：`npm run fnos:pack`。开发机必须先准备 `.tools/native-runtime-linux` 的生产依赖；可用 `FNOS_RUNTIME_DIR` 指定。只复制实际安装的 Linux x64 运行依赖，不能用 macOS Sharp 交付 NAS。

0.2.2 打包修复：Node 文件复制保留原软链接形式，生产运行目录清理所有 npm `.bin` 命令目录和不使用的 TypeScript 编译器；其余软链接直接阻止构建。旧包存在 9 条指向开发机 `/Users/...` 的链接，不能将本机 tar 能读出归档视为 NAS 解压兼容。`package-files.test.mjs` 覆盖绝对/相对、嵌套命令链接、编译器删除及意外外部链接。

应用中心、桌面、登录页与页眉统一使用用户提供的 `public/brand/shiguang-app-icon.png`（便签纸 + 绿色铅笔 + 回形针），64/256 px 从同一张 1024 px 源图缩放；内置页脚标志为 `public/brand/shiguang-footer-logo.png`。详情见 `fnos-icon.md`。

## 数据与权限

数据在 `TRIM_PKGVAR/data/notes-data.json`，图片在 `TRIM_PKGVAR/images/<scope>/`，共享授权在 `data/shared-spaces.json`。私有 Scope 为 `nas-<UID>`；共享 Scope 为 `space-<UUID>`。

所有请求先验证网关身份，所有写操作验证同源、CSRF 和当前用户绑定。工作区选择必须有权限；共享只有所有者可管理成员，编辑成员可写，只读成员可读/导出。图片、归档任务也校验当前用户，管理员身份不能直接越过私有或共享所有者权限。

原生模式禁止任意 `markdownPath` 和相对服务器图片路径。客户端应读自己的 Markdown 文件后提交正文。旧 M0 正文仅在当前 UID 的完整私有区为空时导入；保留旧文件。工作区条件保存使用单调时间戳，冲突不覆盖；失败后不自动轮询替换草稿。切换空间仅保存本机未完成修改，避免用陈旧副本覆盖另一成员的新内容。

正文不持久写到浏览器。上游外观、页脚等本机偏好仍采用其设置方式。服务密钥保存在应用私有运行目录，不回显到诊断。

## PNG 与归档

七种主题使用原作者 NoteSheet/样式，客户端生成宽 1440 px 的 PNG，单片不超过 1800 px、最多 12 片，包含本机字体与主题边界。PNG 保存采用浏览器下载/可用的系统分享；手机 App 需真机验证。

原生服务不提供后台截图 `/api/export`；旧的外部 PNG 调用不能绕过这项设计。单篇归档包含本地 TTF 字体，不再要求 NAS 安装 Python/fontTools；完整工作区 ZIP 保留上游分类、Markdown、图片及进度业务。

0.7.7 修复原生应用的写操作与登录链路，并重新设计应用图标：

- **写操作校验失败**：原生模式的 CSRF 令牌原先只存在服务端内存里，应用升级或服务重启后页面缓存的旧令牌立刻失效，于是「创建共享空间」「创建用户」和左下角「写入校验失败」同时出现。现在令牌由持久化的会话密钥派生（`createNativeCsrfToken`），跨重启稳定；前端 `appFetch` 遇到过期令牌会刷新会话后自动重试一次。
- **目录授权记不住**：应用原先要求用户手工放 `api-token` 文件，因此飞牛系统接口始终未就绪、刷新或重开都要重新授权。现在打开「文件授权」或点击授权时会通过 `TrimApp.getSessionCredentials()` 取本应用会话凭据并登记到应用数据目录，重启后仍可复用；缺失时面板给出明确说明。
- **退出登录**：退出前的保存请求撞上失效令牌，导致按钮看起来点不动；随写令牌修复后，「账号与同步」与左下角账号菜单都能正常退出并回到登录页。
- **用户管理样式**：该面板渲染时漏了 `.native-settings` 作用域，输入框、按钮与列表退回浏览器默认外观；现已与「账号与同步」其它卡片统一。
- **共享空间**：「返回私有便签」只在处于共享空间时显示。
- **图标**：应用中心与桌面图标改为自绘的「便签纸 + 笔」；页脚标志改为浅米色圆底 + 近白 S（取自原页脚配色）；主题色卡恢复使用原主题插画；补上历史页脚路径迁移，修复老用户升级后的页脚裂图。

## 0.8.0 写校验、目录授权与原生图片

- 飞牛 WebView/反向代理未转发 `Origin` 时，带有效租户绑定和 CSRF 的写请求不再被误判为跨站；存在来源头时仍要求同源。前端在身份或令牌缺失时会重新读取会话再重试一次。
- 目录授权回调改读 `/api/auth/session`，授权列表写回后刷新页面仍可恢复；授权成功时界面直接显示保存的完整路径。
- 系统凭据可用时按实时授权目录复核；旧 Desktop 没有该能力时，仅允许宿主选择器返回且真实存在于用户卷/共享卷的路径，服务端通过 `realpath` 拒绝路径穿越和系统目录。
- NAS 图片选择后会先登记所选真实文件，再由 `/api/fnos/read-image` 校验授权根目录、文件大小和图片类型后读取。
- 删除最后一张正常便签不再自动补一张空白便签；内容保留在回收站，用户点击「新建便签」后才重新创建。

### 0.8.1 真实 WebView 写请求与登录态

- 带有效 `X-Shiguang-User` 与 HMAC CSRF 的写请求不再检查 WebView 的 `Origin/Referer`；
  登录、退出仍要求 HTTP(S) 同源。非 HTTP WebView Origin、反向代理改写 Host 都不会再
  导致新建账号或目录授权失败。
- 网关会话存在时自动进入应用，不依赖可能被 WebView 清理的 localStorage。主动退出会写入
  独立标记，重新打开仍停留在登录页，直到用户重新选择 NAS 或账号密码登录。
- 手机保存按钮会立即提交工作区并等待成功；页面隐藏或 pagehide 时也会排队提交最新快照。
